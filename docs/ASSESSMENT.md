## Executive Summary

The Personal CFO app is feature-complete and well-architected for a v1 single-user tool: encryption-at-rest is applied consistently, config fails fast, requirements are pinned, docker-compose has healthchecks, and the core agent/vault/auth paths carry Pydantic models and a 135-test suite against real Postgres. The foundations are sound. However, it is not yet production-ready for a finance application because of a cluster of correctness and security gaps that are squarely in scope for the standards the project sets itself. The most serious are: four year-versioned tax constants in agent/principles.py are stale and will tell the user lower contribution limits than the law allows (a factual finance error the agent emits verbatim); LLM_TIMEOUT_SECONDS is defined but never wired into the Anthropic client, leaving every LLM call unbounded; the /chat and /intake LLM endpoints have no rate limit despite this being self-flagged as a known gap and a non-negotiable standard; the Coach node appends enriched proposals against an additive reducer (with a misleading "replace" comment), double-counting every proposal the Synthesizer scores; the entire /intake/submit path creates 10+ vault entity types with zero audit-log rows; and the mandated state-specific tax/legal refusal is absent from all prompts and tests.

Secondary but real: the deploy workflow runs Alembic migrations after the new app is already serving traffic; DB sessions are mocked in several tests in direct violation of the "no DB mocking" rule, and the primary /chat endpoint plus /wealth/*, /digest, and /import/transactions have no HTTP-surface tests; the graph routes only one specialist per turn, silently dropping proposals on multi-topic questions; and several frozen CONTRACTS.md interfaces (the /wealth/position key, two computation signatures, three AgentState fields) have drifted from code without the required amendment. None of these are architecturally deep — they are concrete, well-localized fixes. Verdict: good foundations with a focused set of high-severity correctness/security gaps that must close before this is trustworthy for real financial data.

## Cross-Cutting Themes

### Frozen-contract drift without amendment
_Spans: contracts, architecture, wealth-correctness_

Multiple frozen interfaces in CONTRACTS.md have diverged from the implementation with no CONTRACTS.md/DECISIONS.md amendment, as the project's own workflow requires. This spans the /wealth/position response key ('wealth' vs frozen 'allocation'), the missing /wealth/trajectory endpoint, net-worth-trajectory path and shape drift, three undeclared AgentState fields, the user_id parameter and changed return types on compute_wealth_position/compute_income_position, the graph topology (sequential vs the contracted parallel fan-out), and the Retrieval node living in graph.py rather than agent/nodes/. Because downstream issues build against these frozen interfaces, the drift is both a correctness risk and a documentation-integrity risk.

### Unbounded and unthrottled external calls
_Spans: error-handling, resource-lifecycle, config, architecture_

External-call safety is incomplete: the Anthropic client is constructed without the defined LLM_TIMEOUT_SECONDS so all LLM calls are open-ended, SMTP is opened with no timeout, yfinance is called synchronously inside async handlers blocking the event loop, and the LLM-calling endpoints (/chat, /intake/interview, /intake/extract) have no rate limit or Retry-After header. Together these allow a single slow or hostile upstream to exhaust the event loop, thread pool, or LLM budget.

### Audit trail and token accounting are incomplete
_Spans: security, contracts, architecture, coding-principles_

The append-only audit log — the only tamper-evident record of financial-data changes — is bypassed by the entire /intake/submit path, by category-mapping mutations, by the holdings price-refresh, and by the agent's persist_node (which writes no pattern or audit rows). Separately, per-node LLM token usage is logged but never accumulated into AgentState, so persisted spend reflects only the Synthesizer call. Both undercut the observability and integrity guarantees the finance threat model assumes.

### Pervasive copy-paste in the vault and router layers
_Spans: coding-principles, syntax-style, llm-anthropic_

The DRY violations are all in the direction of too little extraction: ~820 lines of identical 16-entity CRUD in vault/crud.py, ~1,050 lines of identical 16-entity 5-endpoint blocks in routers/vault.py, and a ~12-line Anthropic-call scaffold copy-pasted across five LLM nodes (one of which, tax_optimizer, diverged and lost its latency logging). A handful of generic helpers/factories would collapse these by ~80% and make cross-cutting changes (token logging, HTMX branching, audit) single-edit.

### Test gates can pass without exercising the system
_Spans: testing, wealth-correctness_

Several testing rules are violated in ways that let the pre-deploy 'pytest zero failures' gate pass hollow: DB sessions are mocked in memory/digest tests (against the explicit no-DB-mocking rule), OperationalError is caught and silently skipped (so tests pass when the DB is down), the primary /chat endpoint and /wealth/*, /digest, /import/transactions have no HTTP-surface coverage, and the eval harness covers only 2 of 9 agent nodes with no adversarial scenarios. The suite is broad but has blind spots exactly where finance correctness lives.

### syntax-style — `weak`

The codebase is largely clean on naming, debug residue, and print() usage (no print() exists in production paths). However, there are two systemic violations of the CLAUDE.md Code Style rules: (1) 107 FastAPI router endpoint functions and one agent helper are missing return type annotations across six files — a direct violation of "type hints on every signature"; and (2) 169 lines across 26 production files exceed the 100-character limit, with the heaviest concentration in vault/crud.py (59 lines) and routers/intake.py (24 lines). Four `type: ignore` suppressions in two files mask real typing gaps instead of fixing them. No TODO/FIXME, commented-out code, or debug print() calls were found in production code.

### resource-lifecycle — `adequate`

The DB session lifecycle and Redis singleton are implemented correctly. `get_session` uses `async with get_sessionmaker()()` which guarantees the session is closed by SQLAlchemy's async context manager, with an explicit rollback in the except branch. Redis is a module-level singleton with a proper `close_redis()` hooked into the FastAPI lifespan shutdown. The Anthropic client is also a module-level singleton via `get_anthropic()`. Three concrete gaps were found: the Anthropic client has no `aclose()` call in the lifespan shutdown sequence (leaving an httpx connection pool open on process exit); the `conftest.py` test `session` fixture carries a wrong return type annotation that could mislead tooling; and SMTP is opened per-call in `_send_email_sync` which is by design but no timeout is set, risking a hang on a slow SMTP server.

- 🟡 **Anthropic client not closed on lifespan shutdown** (medium)
  - **Files**: `clients.py:49-61`, `main.py:44-56`
  - **Evidence**: clients.py defines `_anthropic: anthropic_sdk.AsyncAnthropic | None = None` and `get_anthropic()` as a module-level singleton. The lifespan in main.py calls `close_redis()` and `dispose_engine()` on shutdown (lines 54-55) but there is no call to close the Anthropic client. `AsyncAnthropic` internally owns an `httpx.AsyncClient` connection pool; not calling `await _anthropic.aclose()` leaves that pool open until the process terminates, producing resource warnings and preventing clean event-loop shutdown in tests that import the app.
  - **Fix**: Add `async def close_anthropic() -> None` to clients.py (mirroring `close_redis`) that calls `await _anthropic.aclose(); _anthropic = None`, then call it in the lifespan shutdown block in main.py after `close_redis()`.
  - **Standard**: CLAUDE.md Phase-4 Resource lifecycle: 'External clients (Anthropic, Plaid, SMTP) module-level singletons' — singleton is present but teardown is absent.
- 🟡 **SMTP connection has no timeout, risking indefinite hang in digest** (medium)
  - **Files**: `digest.py:124-136`
  - **Evidence**: `_send_email_sync` at digest.py:133 opens `smtplib.SMTP(settings.smtp_host, settings.smtp_port)` with no `timeout` argument. The default is `socket._GLOBAL_DEFAULT_TIMEOUT`, which on most systems is `None` (blocking forever). If the SMTP server is unreachable or hangs mid-transfer, `asyncio.to_thread(_send_email_sync, ...)` will block a thread-pool thread indefinitely, eventually exhausting the pool. WEB_STANDARDS.md §4 requires 'Timeouts on every external call'.
  - **Fix**: Add a `timeout` parameter: `smtplib.SMTP(settings.smtp_host, settings.smtp_port, timeout=30)` and expose it as a `SMTP_TIMEOUT_SECONDS` env var, consistent with the existing `LLM_TIMEOUT_SECONDS` pattern.
  - **Standard**: WEB_STANDARDS.md §4: 'Timeouts on every external call — Anthropic, RentCast, yfinance. No open-ended await. LLM_TIMEOUT_SECONDS env var already covers the Anthropic client; verify it's wired to all nodes.'
- ⚪ **Test conftest `session` fixture has wrong return type annotation** (low)
  - **Files**: `tests/conftest.py:83-90`
  - **Evidence**: The fixture is declared `async def session() -> AsyncSession` (line 84) but the function body uses `yield`, making it an async generator. The correct annotation is `AsyncIterator[AsyncSession]` or `AsyncGenerator[AsyncSession, None]`. Mypy and pyright will flag callers that try to type-check the fixture's resolved type, and the mismatch can confuse IDE tooling about what the fixture actually provides.
  - **Fix**: Change the return type to `AsyncGenerator[AsyncSession, None]` (importing from `collections.abc`) or `AsyncIterator[AsyncSession]` (already imported via sqlalchemy at the top of the file).
  - **Standard**: CLAUDE.md Coding Principles: 'Every new function typed' — the existing annotation is structurally incorrect for a generator function.
- ⚪ **conftest clean_users / clean_db fixtures create a fresh sync engine per invocation** (low)
  - **Files**: `tests/conftest.py:59-80`
  - **Evidence**: `clean_users` (line 62) and `clean_db` (line 77) both call `create_engine(get_settings().database_url)` and then `engine.dispose()` at the end of each test run. Each call allocates a new connection pool and immediately tears it down — a churn of at least one TCP connection per test. The `engine.dispose()` is present so there is no leak, but the pattern creates unnecessary connection overhead when these fixtures are used together or in large test suites.
  - **Fix**: Extract a module-level `_sync_engine = create_engine(...)` in conftest.py (created once at collection time) and share it across both fixtures. Call `_sync_engine.dispose()` in a session-scoped `autouse` finalizer, or simply rely on process exit to close it since tests are short-lived.
  - **Standard**: CLAUDE.md Phase-4 Resource lifecycle: 'Test resources cleaned up' — resources are cleaned up but the per-call engine construction is inefficient and contrary to the singleton pattern mandated for external clients.

### Coding principles — DRY / SOLID / KISS — `weak`

The codebase has three significant DRY violations that dominate the findings: (1) a copy-pasted ~12-line Anthropic-call scaffold (client creation, timing, tool-use extraction, logging) is repeated across four LLM nodes with no shared helper; (2) vault/crud.py contains 16 entity-CRUD groups each with identical create/update/delete bodies — ~820 lines that collapse to ~150 with two generic helpers; (3) routers/vault.py repeats the same 5-endpoint router block 16 times, totalling ~1,097 lines where a generic factory would need ~150. The SOLID principle of single responsibility is also violated in coach.py, which conflates arena-context loading, proposal enrichment, and NodeProposal construction into one function. The tax_optimizer node is the only LLM node missing latency instrumentation (KISS inconsistency). No premature abstractions were found; the violations are all in the opposite direction — too little extraction.

- 🟡 **Duplicated Anthropic-call scaffold across 4 LLM nodes (DRY)** (medium)
  - **Files**: `agent/nodes/strategist.py:73-102`, `agent/nodes/career.py:64-89`, `agent/nodes/coach.py:103-135`, `agent/nodes/analyzer.py:63-85`
  - **Evidence**: Every LLM node independently repeats the same ~12-line pattern: (1) `client = get_anthropic()`, (2) `t0 = time.monotonic()`, (3) `response = await client.messages.create(...)`, (4) `latency_ms = int((time.monotonic() - t0) * 1000)`, (5) `tool_block = next(b for b in response.content if b.type == "tool_use")`, (6) a `logger.info("...: tokens_in=%d tokens_out=%d latency_ms=%d", ...)` call with the same format string structure. This block is copy-pasted with minor name substitutions in strategist (lines 73-102), career (lines 64-89), coach (lines 103-135), and analyzer (lines 63-85). synthesizer.py has a slight variant (adds cache_read/cache_write) but shares the same core scaffold. The result is five places where a change to token-logging format, error handling, or cache header would need to be applied manually to every node.
  - **Fix**: Extract a shared `call_llm(client, model, max_tokens, system, messages, tools, tool_name, label)` coroutine in `agent/llm_call.py` that handles timing, the `extra_headers` constant, tool-block extraction, and the standardised token/latency log line. Each node calls it with its label and receives `(tool_input_dict, usage)`. This reduces the per-node footprint from ~12 lines to 1-2 lines and guarantees uniform observability.
  - **Standard**: CLAUDE.md Coding Principles — DRY: 'Extract any logic used more than once.'

### contracts — `adequate`

The codebase is largely faithful to CONTRACTS.md but has several notable divergences.
